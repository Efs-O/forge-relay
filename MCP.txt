### What “External MCP Server” Means

It doesn’t mean a cloud/remote server.  
It means a separate small program (the MCP server) that runs on your computer (local). Codex talks to it via STDIO (standard input/output) — basically launching it as a child process.

This is the recommended and best-supported way for local tools in Codex.

### Local Real-Time / Background Monitoring in Codex

Codex doesn’t have a built-in “Monitor tool” like Claude Code, but you can achieve very similar results using a local MCP server designed for this purpose.

#### Best Option: `background-process-mcp`

This is a popular local MCP server that lets Codex:

- Start long-running commands/processes
- Monitor their output in real-time
- Check status, logs, stop them, etc.
- Works great with Codex’s `/goal` loop

How to install and add it locally:
 Add this to your `~/.codex/config.toml`: 
toml
[mcp_servers.backgroundProcess]
command = "npx"
args = ["@waylaidwanderer/background-process-mcp@latest"]

 Restart Codex (or run `codex mcp refresh`). 
Once added, Codex can use tools from this MCP server to start a process and monitor it without constant polling.

### Other Good Local Monitoring Options

- Filesystem watchers (via other MCP servers)
- Custom simple MCP servers (many people write their own in Node.js/Python for specific needs like watching logs or file changes)

### Summary for You

- You can do everything locally — no need for remote/cloud servers.
- Use STDIO-type MCP servers (they run as local processes).
- Combine the background-process-mcp with Codex’s `/goal` for monitoring behavior similar to Claude’s Monitor + Loop.
